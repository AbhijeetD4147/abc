# Message Feature Development Planning

## Project Overview
- **Project**: React Patient Portal for MaximEyes
- **Feature**: Message System
- **Current Status**: Phase 1 Complete (Mock Data), Feature On Hold

## Current Implementation Analysis

### Original Message.tsx Structure
- **File Size**: Large monolithic component (1227 lines)
- **Main Sections**:
  - Imports and interfaces
  - State management (multiple useState hooks)
  - Helper functions
  - useEffect hooks
  - Complex JSX layout with sidebar and content areas

### Key Components Identified
- Message sidebar with search and list
- Message content area with header, compose form, and message view
- Bulk selection functionality
- Search and filtering capabilities
- Message actions (send, reply, forward, archive, delete)

## Refactoring Plan (Proposed)

### Phase 1: Data Separation ✅ COMPLETED
- **File**: `src/data/messageData.ts`
- **Content**: 
  - Message interface definition
  - 10 sample messages with realistic medical scenarios
  - Helper functions for filtering and searching
- **Status**: ✅ Implemented

### Phase 2: Custom Hooks (Planned)
- **useMessageState.ts**: Manage message state, selected messages, compose state
- **useMessageSearch.ts**: Handle search functionality and filtering
- **useBulkSelection.ts**: Manage bulk operations and selection state
- **useMessageActions.ts**: Handle send, reply, forward, archive, delete actions

### Phase 3: Component Breakdown (Planned)
- **MessageSidebar.tsx**: Left panel with search and message list
  - MessageSearchBar.tsx
  - MessageList.tsx
  - SidebarHeader.tsx
- **MessageContent.tsx**: Right panel with message details
  - MessageHeader.tsx
  - ComposeForm.tsx
  - MessageView.tsx
- **Message.tsx**: Main container (simplified)

## Technical Decisions

### Architecture Choices
- **State Management**: React hooks (useState, useEffect)
- **Styling**: Tailwind CSS
- **Icons**: Lucide React
- **File Structure**: Feature-based organization
- **Data Flow**: Props drilling (to be optimized with Context API)

### Mock Data Structure
- **Messages**: 10 realistic medical scenarios
- **Categories**: general, appointment, billing, medical, prescription, lab_results, insurance
- **Types**: inbox, sent, draft, archived, deleted
- **Priorities**: low, normal, high, urgent
- **Features**: attachments, encryption, tags, timestamps
